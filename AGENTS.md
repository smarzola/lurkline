# Project Instructions

- Keep `lurkline` read-only unless a goal explicitly broadens its Slack capabilities.
- Never commit, log, snapshot, or print real Slack tokens, cookies, HAR payloads, workspace messages, or user data.
- Keep CLI and MCP behavior backed by the same typed service layer.
- Use synthetic fixtures for tests and examples.
- Run formatting, lint, tests, and release build before publishing changes.
