# Goal: Lurkline v0.4.1 Self-DM Draft Compatibility

Work in
`/Users/smarzola/Documents/Codex/2026-07-26/use-browser-to-read-sferait-ws/lurkline-v041`.

Deliver Lurkline v0.4.1 end to end. Accept Slack's validated `user_ids`
enrichment on self-DM draft destinations so a successful `drafts.create`
acknowledgement is returned as success instead of inviting a duplicate retry.
Preserve fail-closed handling for malformed identifiers, unknown private-API
destination fields, unsupported content, and ambiguous message publication.

Source of truth: this goal, the current repository behavior, and the
credential-safe evidence from the authorized v0.4.0 live self-DM smoke test.

## Target State

When this goal is complete:

- Draft destinations retain a known, typed `user_ids` list in CLI and MCP JSON.
- Valid Slack-enriched self-DM drafts are supported across list, get, create,
  update, delete, and publication.
- Draft creation accepts validated response enrichment without weakening the
  requested channel, thread, or broadcast identity check.
- Malformed user IDs and every genuinely unknown destination field remain
  invalid or unsupported before mutation or publication.
- Package metadata, help-facing examples, README, and release artifacts
  consistently describe v0.4.1.
- A reviewed pull request is green and merged, `v0.4.1` points at merged
  `main`, and the three platform archives and their checksums are verified.

## Constraints And Non-Goals

Follow `AGENTS.md`.

- Treat `channel_id` as the authoritative destination. `user_ids` is validated
  Slack metadata and must not override the channel, thread, or broadcast route.
- Preserve `user_ids` when Slack returns it and when an existing draft is
  updated. Do not synthesize participants that Slack did not return.
- Validate every returned user ID with the established Slack user-ID rules and
  bound the list. Reject malformed response shapes rather than coercing them.
- Continue to retain unknown destination fields for diagnostics while marking
  those drafts unsupported for mutation or publication.
- Do not broaden authoring to arbitrary destinations, files, attachments,
  scheduling, editing sent messages, or new Slack APIs.
- Use only synthetic identifiers and payloads in committed tests and examples.
  Never commit or print real credentials, HAR data, workspace messages, draft
  content, conversation IDs, user IDs, or draft IDs.
- Leave the existing live smoke-test draft untouched.
- Implement the smallest coherent fix that completely covers the shared typed
  service, CLI, MCP, documentation, versioning, and release.

## Success Criteria

The goal is complete only when:

1. `DraftDestination` exposes a typed `user_ids` field and preserves it in
   stable JSON without placing it in `extra`.
2. Response normalization validates the `user_ids` count and each identifier,
   accepts the live-shaped self-DM destination, and rejects malformed values.
3. Create acknowledges Slack-added `user_ids` while still requiring the exact
   requested channel, thread, and broadcast route.
4. List, get, update, delete, and send treat an otherwise-supported enriched
   self-DM draft as supported; update preserves returned `user_ids`.
5. Unknown destination fields, files, attachments, invalid routing, non-rich
   blocks, sent drafts, and deleted drafts remain unsupported or invalid.
6. Synthetic service, HTTP, CLI/MCP schema, and regression coverage prove the
   fix and the fail-closed boundaries without real Slack data.
7. README follows Google developer documentation guidance and accurately
   describes known destination metadata and private-API compatibility.
8. Crate, lockfile, MCP, package, help, and README version references are
   consistently v0.4.1.
9. Formatting, lint, all locked tests, locked release build, help/package
   smoke tests, credential scan, and diff validation pass.
10. A credential-safe live test confirms the existing draft is now supported
    and a newly created self-DM draft returns success and can be deleted. The
    pre-existing live draft remains untouched.
11. Persistent adversarial review and a fresh independent final audit report
    no blocking findings.
12. The pull request is green and merged, `v0.4.1` points at merged `main`, and
    the release contains three valid archives and three matching checksums.
