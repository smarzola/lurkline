# Goal: Lurkline v0.2.0 Discovery, Search, And Inbox

Work in `/Users/smarzola/projects/lurkline`.

Deliver a release-ready local v0.2.0 implementation in which humans and agents can discover Slack conversations, search workspace messages with bounded filters, address conversations by human-readable names, continue paginated reads, and obtain one bounded unread inbox snapshot without maintaining local state. CLI and MCP must expose the same typed, read-only service behavior.

Source of truth: the user-approved “v0.2.0: discovery and inbox” scope in the current Codex task, refined by repository evidence.

## Target State

When this goal is complete:

- Users and agents can list and find channels, DMs, and group DMs with stable typed metadata and enforced scan/result bounds.
- Users and agents can search messages with optional conversation and date filters, stable typed matches, deterministic newest-first ordering, and cursor/result bounds.
- Commands and tools that read a conversation accept either its Slack ID or an unambiguous exact human-readable name; IDs remain a zero-discovery fast path.
- Channel and thread reads accept Slack cursors and faithfully return the next cursor.
- One bounded inbox operation resolves unread conversation names and returns recent message context plus Slack’s unread-thread summary without marking anything read.
- The crate, MCP server, package metadata, tests, and task-oriented README consistently describe version 0.2.0 and its behavior.

## Constraints And Non-Goals

Follow `AGENTS.md`.

- Keep every Slack operation read-only and authenticated only from the existing environment configuration.
- Keep CLI and MCP behavior backed by the same typed service layer.
- Never commit, log, snapshot, or print real Slack credentials, HAR payloads, workspace messages, identifiers, or user data; tests and examples use synthetic fixtures.
- Preserve 0.1.0 command compatibility. Existing Slack IDs remain accepted without a conversation-list request.
- Enforce finite page sizes, scan limits, result limits, duplicate-cursor detection, response-size limits, and input validation.
- Conversation-name resolution is case-insensitive exact matching after an optional leading `#` or `@` is removed. It must reject missing and ambiguous matches rather than guessing. Substring matching belongs only to the explicit find operation.
- Message search uses the read-only `search.messages` method. It accepts a non-empty query, optional ID-or-name conversation filter, optional validated `YYYY-MM-DD` `after`/`before` dates, an optional cursor, and a result limit from 1 through 100. It requests timestamp-descending results without highlights and exposes Slack-reported totals/cursors honestly.
- Inbox is a bounded, on-demand snapshot. It may read recent history for selected unread conversations and return Slack’s unread-thread counts, but must not infer exact unread message boundaries or thread roots that Slack did not provide.
- Do not add credential extraction, credential persistence, a cache/database, daemon, browser automation, writes, installers, shell completion, registry publication, tags, pushes, or GitHub releases.
- Implement the smallest coherent complete design. Prefer direct code and existing patterns over new dependencies, generalized repositories, caches, or speculative abstraction.

## Success Criteria

The goal is complete only when:

1. CLI `conversations list`, `conversations find`, `search messages`, and `inbox` commands produce concise human output and stable JSON, with tested limits, empty results, pagination, malformed responses, and ambiguity/not-found behavior.
2. MCP exposes matching `slack_list_conversations`, `slack_find_conversations`, `slack_search_messages`, and `slack_read_inbox` tools with structured schemas/errors and read-only annotations.
3. Message search supports optional conversation, `after`, `before`, cursor, and limit inputs end to end; resolves conversation names safely; returns normalized channel/message metadata, totals, and continuation state; and never exceeds Slack’s 100-result bound.
4. Channel/thread/message reads accept an ID or exact conversation name; an ID performs no discovery call; ambiguous or absent names fail explicitly.
5. Channel and thread reads accept an optional cursor end to end through CLI, MCP, service, HTTP request, and synthetic request-shape tests.
6. Inbox returns at most the requested unread conversations and messages per conversation, includes resolved conversation metadata and Slack’s unread-thread summary, accurately reports truncation, and never mutates Slack state.
7. Package and MCP versions are 0.2.0; README and help text document the complete current command/tool contract and its honest private-API limitations.
8. Existing 0.1.0 behavior, security invariants, raw stdio protocol behavior, package checks, formatting, lint, tests, and locked release build remain green.
9. Every milestone is adversarially reviewed, checked off with exact verification evidence, and committed with a focused Conventional Commit; a fresh independent final audit reports no blocking findings.
