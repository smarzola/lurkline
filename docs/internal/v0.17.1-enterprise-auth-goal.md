## Outcome and scope

The standard clipboard import accepts HTTPS API requests from one-label Slack
workspace hosts and one-label `enterprise.slack.com` hosts. Ordinary `T…`
routes still work. Enterprise routes containing an `E…` organization prefix
and a final `T…` or `E…` context ID are validated and normalized to that final
ID, as are standalone Enterprise IDs. Existing profile storage remains compatible.

The baseline repeats the hostname check in three places in `config.rs` and
`curl_import.rs`; the importer only accepts alphanumeric `T…` routes. Profile
storage already accepts standalone `E…` identifiers. HTTP session validation
uses `client.counts` and constructs a client referer from the context ID.
The checkout was clean and matched `origin/main`; latest release was `v0.17.0`.

Decisions: share the hostname predicate to keep import, configuration, and
service origin validation aligned. Normalize the route at import, preserving
the current credential format and HTTP behavior. Do not allow arbitrary Slack
subdomain depth or broaden Slack operations. No new dependencies are needed.
This fixes the reported import restrictions; it does not certify all Enterprise
Slack features or replace real-session verification by the user.
